## 2026-07-31 - [Parser-Differential Scanner Bypass via Unclosed Frontmatter]
**Vulnerability:** In `stripFrontmatter`, if a markdown file started with `---` but had no matching closing `---` later, the function assumed the entire file was metadata (frontmatter-only) and returned an empty string for the markdown content. Since the security scanner only scans the returned markdown content, unclosed frontmatter blocks effectively bypassed all security scan rules while still allowing downstream YAML parsers/compilers to parse and compile the remaining content as executable markdown body.
**Learning:** Security filters must not fail-open or make overly permissive assumptions (like returning empty content on malformed metadata bounds). If metadata framing is malformed or unclosed, the entire input must be treated as untrusted payload and processed fully by all security rules.
**Prevention:** Always default to scanning the entire file content if metadata delimiters are missing, unbalanced, or malformed. Ensure parser-differentials are eliminated by using identical boundaries across parsing and scanning components or defaulting to the most restrictive/comprehensive processing when in doubt.
