## 2026-07-18 - Avoid Redundant Regex Scans Before Replacements
**Learning:** Adding a `MatchString` guard before a regex replacement (`ReplaceAllString` or `ReplaceAllStringFunc`) is a micro-pessimization for the matching case. If the string matches, the regex engine compiles/runs twice (once for the match check and once for the replacement), doubling the execution overhead. Instead, use extremely lightweight substring checks (like `strings.Contains`) to fast-path exclude non-matching cases, and let the replacement method handle matches directly.
**Action:** When designing fast paths, only use basic substring checks to bypass regex. Avoid adding `MatchString` guards before replacements unless the replacement case itself is exceptionally rare and has extremely high allocation overhead that `MatchString` avoids.
